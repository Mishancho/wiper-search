# Персональный рабочий поиск артикулов

Дата: 2026-09-29

## Цель

Ускорить повседневный поиск аналогов на одном рабочем компьютере. Пользователь должен быстрее повторять недавние запросы, копировать найденные номера и видеть, каких артикулов не хватает в базе.

Решение остаётся персональным инструментом. Оно не добавляет аккаунты, серверное хранилище пользовательских данных, совместную работу или отдельную административную систему.

## Контекст

Приложением почти всегда пользуется один человек на одном рабочем компьютере. Google Sheets остаётся источником поисковой базы, а Flask-приложение отвечает за поиск по её кешированному снимку.

Поэтому история, избранное и список ненайденных запросов хранятся в браузере через `localStorage`. Очистка данных браузера удалит эти персональные данные, но не изменит Google Sheets и поисковую базу.

## Состав первой версии

### Единый русский интерфейс

Заголовки, подсказки, состояния загрузки, ошибки и результаты переводятся на русский язык. Текст интерфейса описывает обе поддерживаемые категории: дворники и тормозные колодки.

Категория и секция результата показываются понятными русскими названиями. Неизвестная секция отображается нейтрально и не мешает поиску.

### Нормализация артикула

Поиск не зависит от:

- регистра;
- пробелов;
- дефисов;
- точек.

Например, `6R1 998 002`, `6R1-998-002` и `6R1998002` считаются одним запросом. Одно и то же правило применяется к пользовательскому запросу и артикулам поискового индекса.

Другие символы автоматически не исправляются. Приложение не подменяет введённый артикул похожим номером и не использует нечёткий поиск, чтобы не показывать потенциально неверную деталь.

В результатах сохраняется исходное написание артикула из Google Sheets.

### История поиска

После каждого завершённого поиска запрос добавляется в локальную историю независимо от того, найден он или нет.

- Хранятся последние 20 уникальных нормализованных запросов.
- Повторный запрос поднимается в начало списка, а не создаёт дубль.
- Нажатие на элемент истории сразу повторяет поиск.
- Пользователь может очистить всю историю отдельной кнопкой с подтверждением.

История располагается рядом со строкой поиска и не занимает место, пока пуста.

### Избранное

Любой введённый или найденный артикул можно закрепить в избранном.

- В избранном хранится нормализованное значение и последнее отображаемое написание артикула.
- Нажатие на избранный артикул запускает поиск.
- Повторное нажатие на действие закрепления удаляет артикул из избранного.
- Избранное сохраняется без фиксированного малого лимита, но интерфейс остаётся компактным.

### Копирование

Каждый артикул в результатах выглядит как интерактивный элемент. Нажатие копирует только этот номер в буфер обмена и кратко подтверждает действие без модального окна.

У каждой группы результата есть действие «Копировать все». Оно копирует основной артикул и аналоги одной группы в читаемом текстовом формате, без технических полей.

Если Clipboard API недоступен, приложение использует безопасный браузерный резервный способ. При полном отказе копирования показывается понятное сообщение, а результат остаётся на экране.

### Ненайденные артикулы

Если поиск успешно завершился пустым результатом, запрос попадает в локальный список ненайденных.

Для каждой уникальной нормализованной позиции хранятся:

- последнее введённое пользователем написание;
- число неуспешных поисков;
- дата и время последней попытки.

Сетевые ошибки, неготовый кеш и ошибки сервера не считаются ненайденными артикулами. Если ранее ненайденный номер позднее появился в базе и поиск стал успешным, он автоматически удаляется из списка.

Пользователь может повторить поиск нажатием на позицию или очистить весь список с подтверждением.

## Компоновка интерфейса

Основной экран остаётся одноэкранным:

1. заголовок и короткое описание;
2. строка поиска;
3. компактные блоки «Избранное» и «Недавние»;
4. состояние поиска или результаты;
5. сворачиваемый блок «Не найдено в базе»;
6. подпись об автоматическом обновлении данных.

История и вспомогательные списки не должны конкурировать с главным действием. Пустые блоки скрываются. На узком экране элементы переносятся по строкам, а копирование и повторный поиск доступны без наведения мыши.

## Поток данных

```text
ввод пользователя
    |
    +--> нормализация для поиска
    |
    +--> POST /search
              |
              +--> найдено: показать результат,
              |             добавить в историю,
              |             убрать из списка ненайденных
              |
              +--> не найдено: показать пустой результат,
              |                добавить в историю,
              |                увеличить локальный счётчик
              |
              +--> ошибка: показать ошибку,
                           не учитывать как ненайденный артикул

localStorage <--> история, избранное, ненайденные запросы
Google Sheets --> серверный поисковый кеш --> POST /search
```

## Хранение и совместимость

Для каждого локального набора используется отдельный версионированный ключ. Чтение данных выполняется защитно: некорректный JSON, неизвестная версия или неправильная структура не должны ломать основной поиск. Повреждённый набор сбрасывается отдельно, без удаления остальных данных.

Приложение продолжает работать, если `localStorage` заблокирован: поиск и результаты доступны, но персональные списки действуют только до перезагрузки страницы или скрываются с ненавязчивым предупреждением.

Никакие персональные данные не отправляются на сервер дополнительно к обычному поисковому запросу.

## Обработка ошибок

- Пустой запрос не отправляется на сервер.
- Ответ `503` о загрузке кеша не попадает в список ненайденного.
- Сетевой сбой не изменяет счётчик ненайденных запросов.
- Ошибка локального хранилища не блокирует поиск.
- Ошибка копирования не очищает и не скрывает результат.
- Действия очистки требуют подтверждения и затрагивают только выбранный локальный список.

## Проверка

### Сервер

- Эквивалентные варианты с пробелами, дефисами и точками находят одну группу.
- Нормализация не меняет исходное написание в ответе.
- Один артикул по-прежнему может вернуть несколько групп.
- Поиск дворников и тормозных колодок сохраняет текущее поведение.

### Браузерная логика

- История ограничивается 20 уникальными запросами и правильно переставляет повторный запрос.
- Избранное добавляется, удаляется и восстанавливается после перезагрузки.
- Счётчик ненайденного увеличивается только для успешного пустого ответа.
- Успешный последующий поиск удаляет номер из списка ненайденных.
- Повреждённые локальные данные не ломают страницу.
- Копирование одного артикула и всей группы выдаёт ожидаемый текст.

### Пользовательский сценарий

На рабочем компьютере пользователь должен суметь:

1. найти артикул с пробелами или дефисами;
2. скопировать один номер и все аналоги;
3. повторить поиск из истории;
4. закрепить и открыть избранный номер;
5. увидеть повторяющийся ненайденный артикул и его счётчик;
6. обновить страницу и сохранить персональные списки.

## Не входит в первую версию

- аккаунты и авторизация;
- синхронизация между устройствами;
- серверная база пользовательских данных;
- запись статистики в Google Sheets;
- массовый поиск;
- нечёткий поиск и автоматическое исправление опечаток;
- поиск по автомобилю;
- цены, остатки и интеграции с поставщиками;
- камера, штрихкоды и распознавание фотографий.
