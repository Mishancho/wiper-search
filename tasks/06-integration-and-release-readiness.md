# 06. Интеграционная проверка и готовность к выпуску

Статус: не начата  
Зависимости: 01, 02, 03, 04, 05

## Цель

Проверить весь персональный сценарий как единое поведение и подготовить безопасное обновление приложения без добавления нового функционала.

## Объём

- Проверить совместную работу нормализации, истории, избранного, копирования и журнала ненайденного.
- Устранить только интеграционные дефекты и расхождения с утверждённым дизайном.
- Обновить версию кеша Service Worker, чтобы старые ассеты не оставались после выпуска.
- Проверить стратегию Service Worker: запросы `POST /search` не должны кешироваться как статические данные.
- Обновить README с новым пользовательским поведением и ограничениями локального хранения.
- Зафиксировать команды тестирования и результаты ручной браузерной проверки.

## Предполагаемые файлы

- `static/sw.js`
- `README.md`
- тесты и файлы, затронутые исправлением интеграционных дефектов

## Критерии приёмки

- Все критерии задач 01–05 выполняются вместе.
- Повторный поиск из истории, избранного и журнала использует одно поведение.
- Ошибки API не записываются как ненайденные позиции.
- Очистка одного локального списка не затрагивает остальные.
- После перезагрузки сохраняются история, избранное и журнал.
- После обновления Service Worker браузер получает актуальные HTML, CSS и JavaScript.
- README соответствует фактическому интерфейсу.
- В итоговой проверке нет новых ошибок в консоли браузера.

## Обязательный пользовательский сценарий

1. Найти существующий артикул с пробелами или дефисами.
2. Скопировать один номер и всю группу.
3. Повторить запрос из истории.
4. Добавить артикул в избранное и найти его оттуда.
5. Дважды найти отсутствующий артикул и увидеть счётчик 2.
6. Имитировать сетевую ошибку и убедиться, что счётчик не изменился.
7. Добавить ранее отсутствующий артикул в тестовый снимок и убедиться, что запись удалена из журнала после успешного поиска.
8. Перезагрузить страницу и проверить сохранность локальных списков.

## Проверки

- Запустить весь набор автоматических тестов.
- Выполнить обязательный сценарий в desktop-браузере.
- Проверить одну узкую мобильную ширину на отсутствие поломки компоновки.
- Проверить приложение с пустым, заполненным, повреждённым и заблокированным `localStorage`.
- Проверить холодную загрузку и обновление уже установленной PWA.

## Не входит

- дополнительные продуктовые функции;
- деплой без отдельного прямого запроса пользователя;
- изменение Google Sheets;
- серверная аналитика.
